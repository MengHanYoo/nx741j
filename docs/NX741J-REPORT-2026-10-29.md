## 2. 今天修掉的四个根因

### 2.1 卡 logo = MobileGestalt 缓存缺失（最耗时）

镜像里有 MG 容器目录但没有缓存文件；libMobileGestalt 走「首次创建」路径，
在 containermanagerd 未就绪时死等信号量 → lsd 全线程阻塞 → LaunchServices 建库永不完成。

**修复**：写入 `com.apple.MobileGestalt.plist`（`CacheVersion=1` + 空 `CacheData`）。

**后果**：同一次开机由「永久卡 logo」变为「19 分钟内进锁屏」。
（后来发现假缓存会让「设置 → 关于」卡死，已在后续镜像中删除，改由 iOS 自己生成。）

### 2.2 启动慢 = 数据分区没有 LaunchServices 数据库

本地镜像每次写回都会抹掉 iOS 启动时建的库，于是每次开机重建（约 15 分钟）。

**修复**：成功开机一次后，用 `pull_iosroot.ps1` 把 16 GiB 镜像**从手机拉回**，
保存为 `iosroot-GOLDEN.img`（`csstore ×2`、MG 缓存、100 个容器）。之后所有实验只换内核/payload。

### 2.3 插件不加载 = 三个配置缺失

| 缺失 | 现象 | 修复 |
|---|---|---|
| `pandora_gpu=14` | 用户客户端不完整 | **`pandora_gpu=15`**（上游 `gpu_test.sh: LEVEL=15`） |
| 无 `NativeAdrenoMetal.clients` | 插件不给任何进程设备 | `/System/Library/Extensions/NativeAdrenoMetal.clients`，内容 `backboardd` |
| Turnip 未安装 | 标记解码为 `no-turnip ` | `libvulkan_freedreno.dylib` 放入插件 bundle 目录 + `/usr/lib/` |

### 2.4 Turnip 加载失败 = cdhash 不在信任缓存

`no-device: LoaderNotFound` 的真正含义不是路径错，而是 **AMFI 拒绝 dlopen 未受信的 Turnip**。

**修复**：把 Turnip 的 cdhash（`899d39cd…`）与插件 cdhash（`cbce9ba2…`）
一起并入 static 信任模块（2762 条）。

**效果**：`PANDORA GPU UC: client 0 opened`、`GPU IRQ 1059 fences`、`DCVS busy 99% @ 1050 MHz`。

### 2.5 渲染后挂起 = GPU 缓冲池 extent 上限过低

`client 0 method 2 -> 0xe00002bd`（`kIOReturnNoMemory`）= `NativeAdrenoMethodBoAlloc` 失败，
随后 `PANDORA GPU HANG ×16`。

**修复**：`GPU_POOL_EXTENTS 512 → 1024`，并加分配失败诊断日志
（打印 `bos/extents/free MiB`）。

**效果**：`ALLOC FAIL 0`、`GPU HANG 0`、DCVS 正常变频。

## 3. 关键调试手段：插件进度标记

插件源码内置 `gpu.mark()`：用 `IOServiceOpen(type=0x4147xxxx)` 上报进度。
内核把被拒绝的打开打印成：

```
PANDORA GPU MARK: 4147706e by backboardd
```

解码规则：**低 8 位是 ASCII 字符**，`0x7fff` 是分隔符。实测得到过：

| 消息 | 含义 |
|---|---|
| `no-turnip ` | Turnip 没装/没找到 |
| `no-device device: LoaderNotFound(LoaderNotFound { tried: …` | Turnip 在但 dlopen 被拒（信任缓存） |

这是本项目最有效的 GPU 调试手段，建议长期保留。

## 5. 待修：画面正确性（下一步唯一目标）

### 5.1 实测数据（boot log）

```
SWEET FB: AppleCLCD 1216x2688 stride 4864 at 0xfc800000, default surface 1, presented as 1125x2436
SWEET FB: swap 1 layer 0 surface 4 1125x2436 fmt 0x42475241 bpr 4608 a 0,0 1125x2436 b 0,0 1125x2436
SWEET FB: layers mask 0x80000007 drawn 0x1 gpu 0: [0 BGRA 1125x2436 ...]
```

| 量 | 值 | 说明 |
|---|---|---|
| 面板 | 1216×2688，stride 4864 | Z80 实际分辨率 |
| CA 合成 surface | 1125×2436 | iOS 认为的屏幕尺寸（iPhone X） |
| surface 像素格式 | `0x42475241` = **BGRA** | 4 字节/像素 |
| surface bpr | **4608**（=1152×4，有 27 px padding） | 每行有填充，必须按 bpr 逐行拷 |
| 呈现标记 | `gpu 0` | 该帧走 CPU 路径 |

### 5.2 三个可怀疑点（需一次性查清，不做逐个试）

1. **缩放/裁切**：1125×2436 的 surface 如何映射到 1216×2688 的面板
   （若直接左上角拷贝会留边；若有缩放，插值方式可能造成文字马赛克）
2. **像素格式**：`BGRA`(0x42475241) 与面板扫描格式是否一致；是否存在
   10-bit / UBWC 压缩表面被当线性读
3. **同步**：GPU 写完的 surface 在 CPU 拷贝前是否已 invalidate（源码注释称已做，
   但 `short fence polls timed out 2001` 说明完成语义仍不可靠）

### 5.3 修复策略（要求「彻底修」，不做逐次试错）

- 先用 `pandora_fbdump`（内核已有帧转储机制）把 **CA 合成的 surface** 与
  **写到面板的内容** 各导出一份，逐像素比对 → 一次定位是「格式」「区域」还是「同步」
- 若为格式/UBWC：在拷贝路径实现对应解码或强制 CA 输出线性 8-bit BGRA
  （`tools/metal/backboardd_prefs.py` 的三个开关必须确认生效）
- 若为缩放：改用 GPU 扫描输出（`pandora_scanout=1`）直接扫描 surface，避免 CPU 缩放
- 若为同步：把 fence 完成与 cache invalidate 绑定在同一处（等待 → invalidate → 拷贝）

## 6. 复现清单（新会话可直接照做）

```bash
# 1. 镜像（含插件/Turnip/clients）
write_image.ps1 -Image iosroot-SEAL.img

# 2. 内核（gpu=15 + extent 1024 + 标记日志）
adb push METAL17-boot_a.img /data/local/tmp/m.img
adb shell "su -c 'dd if=/data/local/tmp/m.img of=/dev/block/by-name/boot_a bs=1M conv=fsync'"
adb reboot

# 3. 读日志（解码标记）
adb exec-out "su -c 'pinfile rawread /data/local/tmp/ioslog.img \$(readlink -f /dev/block/by-name/userdata)'" > ioslog.bin
python read_log_boot2.py && python _dm2.py
```

## 7. 经验条目（新增）

1. **GPU 插件要三样东西**：`pandora_gpu=15`、`*.clients` 名单、Turnip 且在信任缓存里。
2. **`LoaderNotFound` 不等于路径错**，优先怀疑签名/信任。
3. **信任缓存的 cdhash 必须只对 CodeDirectory 本身求哈希**（用其 length 字段），
   对整个 superblob 求哈希会得到错误值。
4. **BO 池的 extent 上限会被分配/释放循环打满**，要留足并做合并。
5. **改镜像必须成对刷内核**，否则会出现「内核改了但镜像带封装/旧状态」的假故障。
