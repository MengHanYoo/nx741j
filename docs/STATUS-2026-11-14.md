# Status — 2026-11-14 (UFS takeover, SMMU geometry, ring probe)

Everything below was measured on the NX741J itself; register dumps are quoted from
the panel or from `flash-boota-9008.ps1 -ReadTo`, and function offsets come from
symbolising the panic `pc` against `kernel.macho`.

## Stage 2 of the UFS guide (queue ownership) — passes

`native-ufs-probe=3` stops the firmware request list, zeroes only the slots the
driver uses, forces stream `0x60` to bypass and restarts the list at the firmware
`UTRLBA`:

    NATIVE_UFS adopt: list replaced
    phys=3b00000 hcs=0000010F->0000010F
    is=00000004 db=00000000 rsr=00000001 ba=3b00000 bau=00000000 ie=00000000

`UTRLBA` changes on every boot (seen `0x3B00000`, `0xC3B05000`, `0xC3AF9000`),
so it must be read from the registers each time and never cached.

## Adopt-path faults found and fixed

| Where | Symptom | Cause |
|---|---|---|
| `adoptAndRead+0x844` | data abort, `far` = mapping base + 0x4000, `esr=0x96000047` | the path mapped 16 KiB of the firmware list but cleaned 32 KiB |
| SMMU planner | abort inside `smmuBypassStream+0xc0` | `IDR1=0x60000051` gives pages=128, banks=81 → `0xD1000` > the `0xD0000` window |

`SMMU_SCR0=0x002e0406` (bit0=0: SMMU disabled), `GFSR=0`, and stream `0x60` has
`SMR=0 / S2CR=0` (no match entry), so the patch writes `S2CR[0x60]=1` and skips the
context-bank planner entirely.

## Doorbell — the remaining blocker

`probe=4` panics immediately before `write32(hc, 0x58, 1)`. The state at that
instruction is correct on every run:

    NATIVE_UFS ring-before
    hcs=0000010F rsr=00000001 dbr=00000000 is=00000000 utrlba=c3af9000
    utrlrsr=00000001
    utrd0=10000000 utrd2=0000000F utrd4=c3afa000 ie=00000000

`utrd0=0x10000000` has no bit24, `utrd2=0x0F` is "not completed", UCD is
`list+0x1000`. The next instruction is the doorbell, and after it the thread never
returns: the boot log continues on other CPUs and stops at `No POST boot-arg set.`
(printed late by `xnupost_run_tests`).

## Log channel

`patches/xnu/0021-console-log-capture.patch` mirrors `console_printbuf_putc` into a
128 KiB BSS buffer; the loader scans DRAM and writes `NXLGST1` + the text to
`rawdump` (LBA `4764464` / `4764465`); `flash-boota-9008.ps1 -ReadTo` reads it back.
First end-to-end capture: 4999 bytes, archived as
[`logs/2026-11-14-nxlog-4999.txt`](logs/2026-11-14-nxlog-4999.txt) (bit flips are
visible there: that boot predates the `dc cvac` fix in 0021).

Observations from that capture:

* a *hung* boot does write the buffer (`matches=1`, len 4999);
* the *panic* boot's text is not in DRAM (no `ring-before` in any buffer), so panic
  output does not go through `console_printbuf_putc` — it needs the
  `consdebug_putc` path as well;
* entering 9008 re-initialises DDR and wipes DRAM, so the loader must run between
  the panic boot and EDL.
