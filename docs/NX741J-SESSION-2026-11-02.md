### 1.2 壁纸缺失的根因链（有日志证据）

| 环节 | 证据 |
|---|---|
| 镜像不是“部分提取” | `mkiosroot.sh` 从 IPSW 三个 DMG（OS + SystemOS + App cryptex）全量 rsync；挂镜像核对：`/Library/Wallpaper/Collections` 完整、`PosterBoard.framework` 在、`/private/var` 有 preferences |
| 壁纸资源齐全 | iOS_16 的 7400.WWDC_2022 三个尺寸都在，3 个 `.ca` 层 + 5 个 HEIC 资产 |
| **PosterBoard 从未打开 GPU** | 197 s 日志里 `client N opened by` 只有 backboardd 的 3 个 client |
| **壁纸扩展被 SIGKILL** | `CRASH CollectionsPoste … sig 9 … reason ns 7 code 0x3: extension check-in timeout`（26 次） |
| 照片库守护崩在启动 | `assetsd` 与 `MobileSlideShow` **同一个 pc `0x20c317198` / lr `0x21b8a65f8`**，`sig 6` + `ns 2 code 0x6`（abort） |
| 设置崩 | `Preferences` `sig 5`（SIGTRAP）+ `sig 11`（SIGSEGV），`ns 2 code 0x5` |

也就是说：壁纸不是没画出来，而是 **PosterBoard/CollectionsPoster 在 check-in 阶段就被杀**，照片/壁纸共用的入口（assetsd 同一 pc）先崩了。

## 3. 环境备忘

- **7-Zip 能读 HFSX 镜像**（`7z l iosroot-SEAL.img` → `Type = HFS, Method = HFSX`），可直接抽/列文件，比每次开 QEMU 快；
- WSL 没有 hfsplus 模块，**写镜像**只能 QEMU + `hfsplus.ko` initramfs；
- `pinfile rawwrite` 推 17 GB 约 270–362 s，保持 extents 不变；
- 日志解析：`_log54.py` 拉 `ioslog.img` 并写 `ioslog_m*.txt`；`pandora-metal pipe split` 是纯文本行，st 状态行在 mark 流里。
