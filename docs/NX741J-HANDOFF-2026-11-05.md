## 1. 今天打通的部分（UniXNU 六层链 · 第 1/2 层）

### 1.1 启动镜像格式（✅ 已确认）

本机 ABL/GBL 对 boot 分区 kernel 字段的要求（对照 `NX741_unlock` 的 `uefi_unlock_8e.img` 逐字节验证）：

| 项 | 要求 | 验证方式 |
|---|---|---|
| kernel 内容 | **纯 gzip(shim + FV)** | 解压解锁镜像得到 4,194,416 B，`ARMd` 头 @0x38 + `_FVH` |
| gzip 流之后 | **不能追加任何数据**（设备树也不行） | 解锁镜像 `unused_data = 0` |
| boot 内 ramdisk | **必须为 0**（GKI 约定，ramdisk 在 init_boot） | 解锁镜像 `ramdisk_size = 0` |
| header 版本 | v4 可用 | `mkbootimg --header_version 4` |

之前两次失败（`Failed to load image from partition: Load Error`）的原因就是**追加了 911 KB 设备树 + 内置 64 MB ramdisk**。

### 1.2 FD 基址（✅ 已确认）

- 解锁镜像 shim 头部第 8 字节起的 `text_offset` 字段 = **`0xFF300000`**，`image_size` = `0x400000`；
- 我们原先用 `0xC6900000`（infinitiPkg 的旧值）是错的；
- BootShim 编译参数：`-DFD_BASE=0xFF300000 -DFD_SIZE=0x400000 -DREQUIRES_KERNEL_HEADER=1`。

### 1.3 显示（✅ 已确认）

- 反汇编解锁 FV 的 `SimpleFbDxe`（GUID `dcfd1e6d-…`）得到实际 GOP 参数：`mov w10,#0x4c0` = **1216**、`mov w11,#0xa80` = **2688**；
- 平台 DSC 的 PCD 必须为 `PcdFrameBufferWidth|1216`、`PcdFrameBufferHeight|2688`、`PcdFrameBufferColorDepth|32`；
- 用 1440×3200 / 1200×2688 / 2688×1200 都会花屏。

### 1.4 内存映射（✅ 已修）

`Platforms/ZTE/nx741jPkg/Library/MemoryMapLib/MemoryMapLib.c`：

### 1.5 驱动依赖与顺序（✅ 已修，可复现）

- `EnvDxeEnhanced` 需要 `UefiCfg`（由 **CfgUtilDxe** 提供）与 `DDRGetInfo`/`HWIO` 协议；
- `CfgUtilDxe` 必须排在 **EnvDxe 之前**（当前 APRIORI 57/58/59 行：DDRInfo → CfgUtil → EnvDxe）；
- `CfgUtilDxe` 从原厂 FV 提取：`file-9399aef4-…/section1.pe`。

## 2. 当前卡点（有证据）

屏幕输出：

```
Loading driver ... SmemDxe.efi
ASSERT_RETURN_ERROR(status=Not Found)
ERROR: C90000002:V03000007 IO F541D663-…
ASSERT AutoGen.c +384:!RETURN_ERROR(Status)
```

- `F541D663-4A48-40AA-AABF-FF158CCAE34C` 是 **SmemDxe 的 FFS 文件 GUID**，不是协议；
- **解锁 FV 里是同一个 SmemDxe**，所以解锁 FV 的界面很可能只是 Sec 阶段横幅，DXE 后同样会卡；
- DT 里 SMEM 区域 `0x81D00000 / 0x200000` 与内存映射一致，但 SmemDxe 在入口返回 `Not Found`；
- 推断：经 **BootShim** 进入 UEFI 时缺少 GBL 正常引导提供的上下文（SMEM 初始化/DT 传递）。
