## 1. 今晚解决并验证的问题

### 1.1 映射别名规则（待办 3，0236）——已上机

`bsd/dev/pandora_gpu.c` 按 `NativeAdrenoVm::preflight/exclusivePages` 的语义实现：

- 别名类别 = 写权限（本驱动所有映射固定 normal non-cacheable / outer shareable / unprivileged）；
- 自有内存（BO 池）：单次 `smmu_map_pages` 写完即返回，不做任何别名遍历；
- 导入内存（IOSurface）：只有另一类别存在活映射时才走 `gpu_alias_pass` 逐页比对，跨类别共享或覆盖 BO 池即 `EEXIST`。

METAL53 上机 296 s 的实测：

```
[   296.647] [vm alias] 3811 maps: 2927 skipped (driver memory or one class), 884 checked, 0 refused; ro 20423 rw 154222 pages
[   296.647] [vm map] 2740 live (2562 own 178 imported) 682 MiB
```

→ 自有内存全部落在 skipped；RO/RW 两类并存时 checked 才增长；**refused = 0**，没有任何跨类别共享页。

### 1.2 unmap 的 TLB 分流（待办 1/2，0235）——已上机

```
[   296.647] [vm unmap] 1071 released (365 own 706 imported) 463985 pages, tlb 995 page / 76 asid, 177764 us
```

两条分支（≤512 页走 `ArmSmmu4KSyncContextTlbPages`，更多走 `ArmSmmu4KInvalidateAllOwnedContext`）都在跑，累计 177 ms。
提交路径去掉 TLBIALL 后 296 s 内 **0 SMMU fault**、无 HANG/RECOVER/panic，fps 39.7（600 帧/15.1 s）。

插件侧 `NativeBridgeMetalFrontend.mm`：

- 三个管线创建点用 `nmb_device_shader_cache_stats()` 前后的 `misses` / `driver_misses` 增量判定「首次编译 / 缓存复用」，分别累加到 `gTimePipelineCompile` / `gTimePipelineReuse`；

## 2. 今晚发现并修掉的坑（都会反复咬人）

### 2.1 根镜像改了不等于手机上有（最大的坑）

- payload 的 `--root-extents iosroot_extents.json` 指向手机 `/data/local/tmp/iosroot.img`；
- 只改 PC 上的 `iosroot-SEAL.img` **不会影响手机**，必须 `write_image.ps1 -Image iosroot-SEAL.img` 推送（`pinfile rawwrite`，实测 17,179,869,184 B / 270.7 s / exit 0，extents 不变）；
- 症状：插件改了却没生效、日志里看不到新字段。先查手机上 `stat -c %y /data/local/tmp/iosroot.img`。
- 代价：METAL54 与 METAL55 第一次上机都白跑（手机里还是 10-25 17:29 的旧镜像）。

### 2.2 git push 被 GitHub 拒（大文件）

```
remote: error: File build/xnu-kernel/.../kernel.development.pandora.a is 128.64 MB
remote: error: GH001: Large files detected
```

`build/`（98 个文件，含 128 MB 内核库、60 MB zip）被上一个会话的 handoff 提交一起 add 进去了。
处理：`reset --soft` 合成一个干净提交 → `git rm -r --cached build` → `.gitignore` 加 `/build/` → 重新提交。

### 2.3 直连 GitHub 不通

`github.com` 解析到 `20.205.243.166` 被墙；`git` 支持 `http.curloptResolve`，用 `20.27.177.113` 可通：

```
git -c http.curloptResolve=github.com:443:20.27.177.113 -c http.version=HTTP/1.1 push origin main
```

### 2.4 回 Android 的快速通道：A/B 切换在这台机器上不成立

| 尝试 | 结果 |
|---|---|
| `fastboot` 可用性 | ✅ `unlocked:yes`、`product: canoe`、`current-slot: a` |
| `fastboot --set-active=b` / `set_active b` | ❌ exit 1，ABL 未实现 |
| misc 写 `bootonce-b` | ❌ 被忽略，仍从 `_a` 起，标记未被消费 |
| misc 偏移 2048 写 `slot_suffix=_b` | ❌ 同样被忽略 |

→ 9008 仍是唯一的恢复路径，但**可以不走救砖包**：进 fastboot 后 `fastboot flash boot_a <原版>` + `fastboot reboot`（脚本 `restore_android.ps1`）。
原版 boot_a：`E:\Nubia_Flash_Brick\备份\ZTEToolBoxParBak_2026.10.24_22.38.43.421\images\boot_a.img`（100,663,296 B）。
